# 本地多仓流水线调度器使用手册

---

## 设计背景与解耦哲学

在大规模多代码仓场景下，工程知识库的维护面临独特的挑战：

- 上下文膨胀痛点：在维护数十甚至上百个代码仓库时，若由单一宏观主智能体串行维护所有仓库，跨越多个代码仓的多轮对话历史、代码差异比对与长链路会话会导致智能体上下文窗口急剧膨胀，容易引发注意力漂移与决策精度衰退。
- 长连接脆弱性痛点：大规模代码仓批量巡检通常耗时较长，依赖单次长时间会话维持与云端服务的长连接，极易因网络抖动、套接字超时或网关限制而中断，造成执行流中断与状态不可控。
- 批次耦合风险：若将多仓循环与状态账本硬编码在智能体提示词或沉重的执行框架中，单个代码仓的执行异常往往容易波及整体批次任务。

针对上述挑战，系统确立了调度器与执行智能体深度解耦的核心哲学：

- 调度层轻量收敛：将宏观的多仓批量扫描、断点续传控制、异步状态轮询与防卡死超时等确定性调度逻辑，全部收敛在本地轻量脚本中。本地调度器不承载业务认知，仅负责流水线推进与观测。
- 执行层单仓闭环：远端维护智能体每次唤起仅承接单一目标代码仓，基于当前仓的代码变更深入源码与架构事实，完成单仓知识更新、断链自检自愈与检查点推进，完成后立即销毁会话释放上下文，实现单仓自闭环与资源即时回收。
- 云端检查点为唯一事实源：调度器与维护智能体之间完全无需维护任何易漂移的本地账本文件或外部数据库。云端检查点水位是维护进度的唯一法定基线，两者通过纯动作协议进行解耦交互。

---

## 核心特性

- 原生轻量零第三方依赖：
  - 基于原生 Node.js 内置模块（包含 `node:fs`、`node:path`、`node:child_process`、`node:util`、`node:process` 与 `node:url`）编写。
  - 无需执行额外的包安装命令，环境完全自包含，无外部依赖冲突风险，开箱即用。
- 开放式派发命令模板：
  - 通过 `--dispatch-cmd` 参数接收任意外部派发命令模板。
  - 内置模板引擎自动替换上下文占位符，支持对反斜杠与双引号的安全转义，无缝兼容各类智能体运行时、接口调用与命令行工具。
- 以云端检查点为唯一事实源天然支持断点续传：
  - 调度器直接读取云端 ActionDock 状态库与 `maintenance.list` 动作返回的基线与最新检查点信息。
  - 已经完成检查点推进的仓库自动判定为无变更并予以跳过；未完成或失败的仓库自动纳入待办队列。
  - 调度器无需在本地磁盘记录任何增量标记或中间状态，彻底消除双事实源与状态漂移隐患。
- 异步状态侦听与防卡死保护：
  - 派发外部任务后，本地驱动器以非阻塞机制脱离，不建立脆弱的长时间长连接等待。
  - 本地驱动器以受控探测周期定期轮询云端检查点推进状态，侦听目标仓库是否达到目标提交。
  - 具备单仓最大等待超时机制，超时后自动判定失败并流转至后续仓库，杜绝智能体死锁或执行卡死阻塞整条流水线。
- 终端观测看板与结算报告：
  - 终端看板采用动态原地刷新机制，实时呈现进度条、总体指标、当前活跃仓、单仓耗时与全局总耗时。
  - 流水线结束后自动生成结构严整的 Markdown 格式结算报告并持久化落盘，直观汇总所有仓库的闭环结果。

## 模板引擎占位符字典

在 `--dispatch-cmd` 命令模板中可使用以下占位符，执行时将根据远端扫描结果自动进行上下文替换：

- 仓库标识：`{{repo}}`
  - 对应代码仓名称（例如 `order-service`），由远端扫描条目中的仓库属性或路径名派生。
- 工作区路径：`{{path}}`
  - 远端工作区绝对路径（例如 `/srv/workspace/order-service`）。
- 目标分支：`{{branch}}`
  - 目标分支名称（例如 `release` 或 `master`）。
- 前置检查点：`{{from}}`
  - 前置检查点提交哈希，首次接入建库无基线时取值为 `initial`。
- 目标检查点：`{{to}}`
  - 目标最新提交哈希，对应仓库当前最新 HEAD 提交。
- 待核验提交数：`{{commitCount}}`
  - 待核验的新增提交总数，反映前置检查点至目标检查点之间的提交数量。
- 变动文件总数：`{{changedFilesCount}}`
  - 代码差异涉及的变动文件总数。
- 变动统计摘要：`{{diffSummary}}`
  - 文件变动统计摘要文本，反映修改文件列表或概览。
- 提交日志摘要：`{{commitsSummary}}`
  - 格式化的提交日志摘要文本，包含简短提交哈希与提交说明。
- 指导语模板：`{{prompt}}`
  - 开箱即用的专业单仓维护指导语模板，包含目标基线、工作区绝对路径、六大分类落盘规范、更新门槛四问判定、特权工具自省指令与检查点推进门禁等结构化提示词资产。

模板引擎转义机制说明：

- 模板引擎在替换占位符内容时默认启用安全转义。
- 自动将字符中的反斜杠替换为双反斜杠，将双引号替换为转义双引号，确保在 Shell 命令行双引号字符串传参时不会发生语法截断或注入异常。

## 命令行参数选项一览

命令行驱动脚本支持以下参数选项：

- 客户端配置标识：`--profile <name>`
  - 说明：指定 ActionDock 远端客户端配置标识。
  - 默认值：`skm`。
  - 用途：连接云端知识中枢特权维护平面的身份配置，用于执行状态扫描与检查点水位侦听。
- 外部派发命令模板：`--dispatch-cmd <template>`
  - 说明：外部维护智能体的触发启动命令模板。
  - 默认值：空字符串。
  - 用途：在预演模式下可选，在正式执行流水线时必填。命令中可自由组合模板引擎支持的各类占位符。
- 单仓超时时间：`--timeout <minutes>`
  - 说明：单仓等待检查点推进的超时阈值。
  - 单位：分钟。
  - 默认值：`15`。
  - 用途：在规定时间内若远端仓库检查点未推进至目标提交，则判定当前仓超时失败并继续调度下一个仓库。
- 探测轮询间隔：`--interval <seconds>`
  - 说明：远端检查点推进状态的轮询探测周期。
  - 单位：秒。
  - 默认值：`10`。
  - 用途：控制向云端知识中枢发送状态查询请求的频率，平衡响应灵敏度与网络负载。
- 预演模式：`--dry-run`
  - 说明：仅扫描远端变更并预览待派发命令，不实际触发命令派发与轮询探测。
  - 默认值：`false`。
  - 用途：在正式调度前校验仓库清单、变更提交统计与派发命令模板渲染效果。
- 定向过滤参数：`--only <repos>`
  - 说明：指定仅处理特定的一个或多个仓库。
  - 默认值：`null`（处理全量仓库）。
  - 用途：多个仓库名称采用半角逗号分隔，如 `order-service,cron-service`，常用于单仓排错与定向补齐维护。
- 结算报告路径：`--report-file <path>`
  - 说明：流水线最终 Markdown 结算报告的输出文件路径。
  - 默认值：`maintenance-report.md`。
  - 用途：将维护结果、耗时统计与执行说明保存为磁盘文件，供归档或审计使用。
- 帮助信息：`-h, --help`
  - 说明：打印命令行选项使用说明与模板占位符字典。

## 多形态派发调用实战范例

- Action 派发模式：
  结合 ActionDock 异步调用维护智能体。通过 `--async` 标记触发远端维护动作，将开箱即用的指导语与目标仓库信息传递给远端执行智能体：
  ```bash
  ./bin/pipeline-runner.mjs \
    --profile skm \
    --dispatch-cmd 'ad run my-agent.dispatch --profile skm --async -- repo="{{repo}}" path="{{path}}" prompt="{{prompt}}"'
  ```

- HTTP 接口派发模式：
  通过 Webhook 触发远程智能体或编排服务。使用 `curl` 命令发送包含仓库标识与目标提交的 JSON 结构负载：
  ```bash
  ./bin/pipeline-runner.mjs \
    --profile skm \
    --dispatch-cmd 'curl -s -X POST https://agent.internal/api/dispatch -H "Content-Type: application/json" -d "{\"repo\": \"{{repo}}\", \"to\": \"{{to}}\"}"'
  ```

- 独立命令行派发模式：
  调用本地智能体命令行工具（如 lobster 或自定义客户端）。直接将结构化提示词与目标提交传入本地执行进程：
  ```bash
  ./bin/pipeline-runner.mjs \
    --profile skm \
    --timeout 20 \
    --interval 15 \
    --dispatch-cmd 'lobster run maintainer --repo="{{repo}}" --to="{{to}}" --prompt="{{prompt}}"'
  ```

- 预演预览模式：
  在不执行真实维护动作的前提下，全面检查远端多仓变更状态与命令模板替换结果：
  ```bash
  ./bin/pipeline-runner.mjs --dry-run
  ```
  若需预览指定派发命令的渲染效果，可同时追加 `--dispatch-cmd`：
  ```bash
  ./bin/pipeline-runner.mjs \
    --dry-run \
    --dispatch-cmd 'ad run my-agent.dispatch --profile skm --async -- repo="{{repo}}" to="{{to}}"'
  ```

- 定向维护单仓模式：
  针对单一仓库执行定向核验与闭环测试，快速验证特定仓库的知识维护流程：
  ```bash
  ./bin/pipeline-runner.mjs \
    --only order-service \
    --dispatch-cmd 'ad run my-agent.dispatch --profile skm --async -- repo="{{repo}}" prompt="{{prompt}}"'
  ```

## 执行流程与观测结果

- 核心执行流程：
  - 远端多仓基线扫描：调度器启动后，首先调用 `maintenance.list` 动作获取所有配置代码仓的当前检查点与远端 HEAD 提交。
  - 待处理队列切分：根据 `--only` 参数筛选目标仓库，比对各仓检查点与最新提交，将检查点已对齐且无代码变更的仓库归入已跳过统计，其余仓库按序推入待办队列。
  - 命令模板动态渲染：针对待办队列中的每个代码仓，提取变更摘要与提交清单，构建结构化指导语，将占位符安全替换至 `--dispatch-cmd` 模板中。
  - 异步非阻塞派发：通过底层子进程生成机制异步拉起派发命令，以非阻塞方式触发执行智能体，避免本地调度器建立脆弱的长连接等待。
  - 检查点水位侦听：进入周期性轮询循环，每隔 `--interval` 指定的秒数，向云端中枢请求目标仓库的检查点状态，判定当前检查点是否推进至目标提交。
  - 超时防卡死处置：当单仓等待耗时超过 `--timeout` 指定的分钟数而检查点仍未推进时，调度器主动终止当前仓的等待并记录失败状态，继续调度队列中的下一个仓库。
  - 报告落盘与退出码响应：所有待办仓库处理完毕后，调度器统计成功、跳过与失败数据，生成结构化 Markdown 报告写入指定文件；若存在失败仓库，则将进程退出码置为 1，确保持续集成流水线能够灵敏感知异常。

- 终端实时看板展示说明：
  - 看板输出结构：
    - 进度条：显示整体推进百分比与已处理仓库占比。
    - 统计明细：直观汇总总仓数、已跳过数、已完成数与失败数。
    - 活跃状态：展示当前正在维护的代码仓名称、单仓已耗时以及流水线全局总耗时。
  - 终端适配能力：
    - 在支持 TTY 终端的环境中，调度器利用终端光标控制转义字符实现看板的原地动态覆写，保持输出整洁。
    - 在非 TTY 环境（如重定向至文件或持续集成流水线控制台）中，调度器自动降级为单行文本日志输出，避免输出控制字符乱码。

- 维护结算报告生成逻辑：
  - 概览元数据：清晰列举执行环境配置标识、扫描总仓数、维护成功数、跳过无需更新数、失败或超时数以及流水线总耗时。
  - 仓库明细列表：逐仓记录仓库标识、远端工作区绝对路径、最终执行状态（成功闭环、无需更新或执行失败）、目标检查点提交、单仓处理耗时以及执行说明文本。
  - 审计与追踪价值：生成的结算报告文件（默认为 `maintenance-report.md`）可直接作为知识维护资产的归档凭证，便于后续追溯和审查。
